# Do it. — project notes

- Shared-streak pacts PWA. Read README.md for the product rules (chain, freezes, grace day, timezones).
- Stack: Next.js 16 (Cache Components ON, Partial Prefetching ON), Supabase, web-push. Mobile-only UI (440px column).
- Every page = sync shell + `<Suspense>` around the data component. Anything reading cookies/auth goes behind Suspense; `lib/supabase/server.ts` calls `connection()` first.
- Never show old data (`components/fresh.tsx`, `lib/fresh.ts`, README "Staying current"): every page with someone's data renders `<Fresh stamp={at} />` (`at` from `requireUser()`/`optionalUser()`), and every background refresh goes through `refreshSoon()` (`lib/refresh.ts`), never a bare `router.refresh()`: offline that swaps the app for an error page. A bare one is fine right after a server action succeeds. Pages are sent with `no-store` by `proxy.ts`; `next start` always does that and Vercel doesn't, so check with `curl -I` on prod after a deploy (previews have no env and 500).
- The router keeps the last screens alive (Activity): state survives leaving a screen, and system back shows it as it was. Reset one-off state (a "done" screen, a busy button): key the screen on `bfcacheId`, and don't let anything that clears itself be part of a key (`useHeld` in `lib/explore/handoff.ts`), or a refresh starts the screen over. Call `refresh()` in actions that add or remove a pact.
- Explore (`app/explore`, `lib/explore`): the catalog is `ideas.ts`, 240 KB, so never import `ideas.ts` or `catalog.ts` from a client component; pass `IdeaCard`s or one idea from the server page. `explore.test.ts` runs every level through `createSchema` and `create_pact()`'s rules: keep it passing when either changes. `levelDraft()` turns a level into the create flow's `RuleDraft`, and `createInput()` (`lib/pact-input.ts`) turns a draft into a pact for both. Break ideas need a coded `slug` and never name the habit in a URL or page title. `checked: false` hides an idea's source (`publicIdea()`). Client pieces are keyed by `bfcacheId`: state survives Back and resets on a new visit. No weight, calories, fasting or daily hard training.
- Ask a friend (`idea_asks`, `app/ask/[code]`): only reachable through `create_ask()`, `ask_preview()` (signed out too, so keep it to a first name and idea ids) and `answer_ask()`. The idea page reads `?ask=` in the browser (`useAskCode`) so it stays static, and it has to survive sign-in and "Change everything else".
- Your own number (`pact_members.target`, `lib/own-number.ts`): null is the pact's, 0 is any amount, build pacts only. `PactView` swaps the viewer's number into `pact.target` at the top (`withOwnNumber`), so screens below just read `pact.target`; `EditPact`, `ChangedCard` and `Roster` get the shared pact. A trigger clears numbers when the measure, unit or direction changes. `start_next_level()` goes through `update_pact()`, so level-up has no rules of its own.
- Rounds: "Go again" = `start_next_round()` RPC → new pact with `previous_id`/`round`; lifetime totals in `lib/rounds.ts`. Home hides a finished round once it has a next round.
- Build vs break pacts: `pacts.kind`. Break pacts reuse check-ins (yes) and `misses` (I gave in), ask from 6pm or the next morning, and never send evening pushes or name the habit in a notification (cron `breakMorning`). README "Break a habit" has the rules.
- Check-ins (`app/p/[id]/pact-view.tsx`): the bottom bar stays one row ("Log today" + "Yesterday"); the input lives in `LogSheet` (Today / Yesterday switch, forgot vs made up for yesterday). The make-up card opens the same sheet. Pacts with nothing to measure keep hold-to-check-in in the bar. Break pacts ask today's question in a sheet from a "How did today go?" button.
- Hearts (`hearts` table, `components/hearts.tsx`): double-tap someone else's check-in (Activity or the Today list) for a heart, triple-tap for a fire (`hearts.kind`). Deliberately unannounced (no button, no push); people find it when one lands on their own check-in or through word of mouth. One reaction per person per check-in: fire replaces a heart, never the reverse. Tapping your name in the line takes yours back.
- Earlier days (`app/p/[id]/earlier.tsx`): the log sheet's Earlier tab and the Progress calendars open `DaySheet` for any changeable day; the catch-up card (`catchUpRun()`, 3+ empty days reaching the day before yesterday) saves through `set_days()`, which loops `set_day()`. `previewDays()`/`batchText()` mirror it; keep them in sync. The previews name later days that start counting again and freezes that move to an earlier miss.
- Edit a pact (`app/p/[id]/edit-pact.tsx`, `lib/edit.ts`): name, icon, colour and `subject` are the creator's column grants, any time. Every rule column is written only by `update_pact()`, which refuses once there's a check-in, miss or `day_changes` row; it cleans settings up like `create_pact()` and `draftRules()` does, so keep all three in sync, and any new rule column goes in `RULE_KEYS` too. `pacts.edits` keeps the rules people joined under (one entry per join at most) for the "changed this pact" card. The check-in and miss guards lock the pact row (`for key share`) so a check-in and an edit can't cross; keep that when re-creating them. Setup pickers live in `components/pact-fields.tsx`, shared with the create flow. Offered only in the pact's menu, by the owner's choice.
- Nobody counts toward the chain until their first check-in (`countsFrom` in `lib/streak.ts`, `period_required()` in SQL). The roster says "Hasn't started yet".
- Activity + change a day (`lib/activity.ts`, `app/p/[id]/activity.tsx`, `components/hold-menu.tsx`): hold your own row, it lifts with a menu, "Change" opens the sheet. Days older than yesterday are only written by `set_day()` (it sets `doit.set_day` so `checkins_guard`/`misses_guard` skip their window); it logs to `day_changes`. `previewDay()` mirrors `set_day()`'s freeze refund/spend; keep them in sync. Today's own break-pact "gave in" row offers "Take it back" (`take_back_miss()`, refunds the freeze like `set_day()`).
- Freezes are per person and spend themselves: a miss past the make-up window uses the misser's own freeze; out of freezes, or 3 quiet days (1 silent week), and they're paused until their next check-in (`paused`, `autoFreezes` in `lib/streak.ts`; cron stores the auto rows). SQL can't see pauses, so `use_freezes(pact, periods, covers)` takes who to cover from `planFreezes()`. The old 2-arg `use_freezes` is kept only for the deploy window; drop it in a later migration. Activity and `previewDay()` read the same engine, so auto freezes and pauses show there too.
- Weekly pacts: weeks start on the pact's start day, so always name the end day. `lib/week.ts` (`weekOutlook`) is where someone stands this week (ok / tight / short + what the week's end brings) and must mirror the engine's freeze/pause rules; screens and the cron's weekly heads-up both read it. Build pacts only.
- Streak logic lives only in `lib/streak.ts` (pure, tested). SQL mirrors the rules that must be enforced (check-in window trigger, freeze cap trigger, `create_pact` freeze allowance = `freezesFor`). Keep them in sync.
- New functions start with no EXECUTE for anyone (default privileges, `20261113000000_lock_down_functions.sql`): grant each RPC to `authenticated` (and `anon` only if signed-out pages call it). `drop` + `create` loses grants; `create or replace` keeps them.
- New tables need explicit GRANTs + RLS, even service-role-only ones (enable RLS, add no policies). Local doesn't auto-grant, but hosted prod has: don't treat a missing grant as protection. Column-level UPDATE grants protect fields like `freezes_allowed`, and only work with no table-wide UPDATE grant.
- Local Supabase: `supabase start -x vector,logflare,imgproxy,studio,postgres-meta,edge-runtime,supavisor` (storage IS needed: avatars bucket). OTP emails → Mailpit :54324.
- Profile photos: `profiles.avatar_url` is set only by server actions (Google photo or `avatars/<uid>/…` in our public bucket); client resizes to a 400px JPEG before upload.
- Design tokens in app/globals.css (ink #10143A, mist, ultramarine, sun, ember, ice; per-pact `data-color`). Font: Bricolage Grotesque. Signature elements: "Your lanes" for build pacts and "Calendar and tokens" for break pacts (below). The old chain (components/chain.tsx) is only left in admin.
- Your lanes (`components/lanes.tsx`, `lib/lanes.ts`): a running track with a lane per person (you first, up to 6), on the pact screen and straightened on the home card. Runners move with days passed, so every pact crosses the line on its last day; the lane shows did / froze / missed / late per period, from `Period.counts`/`required`/`paused`. Runner colors go by join order from a per-pact-color palette, so everyone sees the same colors.
- Calendar and tokens (`components/tokens.tsx`, `lib/tokens.ts`): break pacts show the viewer's own clean days (counting check-ins, limit applied; a miss replaces a yes) with tokens at 1, 3, 7, 10, 14, 21, 30, 40, 50, 60, 75, 90 clean days plus a finisher's. Tokens are never taken back. Weekly bars measure against the week's target; milestones past the pact's pace are "bonus". A new token lands with a Burst once per token (localStorage).
- Both play an open animation every time the pact screen mounts (`components/use-run.ts`: runs from 0, then from where it was when data changes; tap skips or replays; reduced motion shows the end state). Home cards play once per session (sessionStorage).
- iOS Home Screen apps can leave fixed/bottom elements a keyboard-height off screen after the keyboard closes (WebKit 297779; iOS 26.0, again in 27 beta). `components/viewport-heal.tsx` (in the root layout) forces a re-measure; the simulators here have the fix, so it can't be reproduced locally.
- Copy voice: plain, sentence case, no "→", no all-caps labels.
- Backlog: `BACKLOG.md`. Whenever we defer something, park an idea from a brainstorm, or the owner mentions a feature they're thinking about, add an entry there (format at the top of the file) without being asked. Check it before starting a related feature.
- Prod: doit.launchit.ae → Vercel `do-it` (fra1) + Supabase `ubdkikowagrmghxsgssi` (eu-central-1). See README "Production". Never `supabase config push` from repo config (would disable Google auth).
- Auth = Google OAuth + iOS handoff (`app/auth/callback`, `app/auth/handoff` confirm step, `app/api/auth/handoff`, `auth_handoffs`). A parked code is only released after "Yes, that was me" in the receiving browser (httpOnly `doit-handoff` cookie). Post-sign-in redirects go through `lib/safe-next.ts`. Email OTP is dev-only.
- Merging to `main` deploys to prod immediately (Vercel Git). Apply migrations before merging; keep them compatible with the live code.
- Contributions: see CONTRIBUTING.md and SECURITY.md. Contributors work from forks and never get production access. Keep CI free of real secrets and on `pull_request`, never `pull_request_target`.
- Admin portal: `/admin`, view-only + test push. Gate = `ADMIN_EMAILS` env (Vercel; never commit an email, the repo is public), checked in `proxy.ts` (404) and again in every `lib/admin.ts` loader / admin server action. Loaders read with the service role, so never export one without `requireAdmin()`.
